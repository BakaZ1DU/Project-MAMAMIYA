# 实现原理与代码结构

## 模块

### `app.py`

- Tkinter 界面；
- 计划列表、编辑器、预览填充、立即发布；
- 后台调度线程；
- 单实例锁；
- 日志写入 `logs/wxrobot.log`。

### `store.py`

- 计划文件夹的读写；
- `post.json` 状态机；
- 发布成功/失败归档；
- 配置读取；
- 图片复制与校验。

### `wechat_ui.py`

Win32 UI 自动化核心：

- `EnumWindows` 找窗口；
- `SetForegroundWindow` / `AttachThreadInput` 聚焦；
- `mouse_event` / `keybd_event` 模拟输入；
- 剪贴板读写；
- 截图颜色定位；
- 发布流程编排。

## 发布流程

```text
ensure_ready()
  ├─ 找微信主窗口（按进程路径过滤）
  ├─ 找不到则尝试启动微信
  └─ 检查锁屏

_normalize_window()
  └─ 最大化 → 还原为普通窗口

_open_moments_page()
  ├─ 如果右上角相机栏已存在，直接复用
  ├─ 先点“发现”面板里的朋友圈行
  └─ 不行再逐个尝试左侧“发现”图标位置

点相机
  └─ 等待标准文件选择框

_select_files()
  ├─ Ctrl+L 地址栏
  ├─ Ctrl+A 清空旧地址
  ├─ 粘贴这条计划的 图片/ 文件夹
  ├─ 点击文件列表 + Ctrl+A
  └─ Enter

_fill_text()
  ├─ 点击编辑框
  ├─ Ctrl+A / Delete 清空草稿
  ├─ 粘贴文案
  └─ Ctrl+A / Ctrl+C 回读校验

_set_privacy()
  ├─ 公开：面板第一行
  └─ 私密：面板第二行

_find_publish_button()
  └─ 在编辑框下半部找微信绿 #07C160 的横向按钮

点发表
  ├─ 等编辑框关闭
  ├─ 等朋友圈信息流重新出现
  └─ 观察“照片未发送”提示条是否增加
```

## 为什么不用固定坐标

微信窗口可能被移动、缩放、最大化，固定坐标很脆弱。代码里尽量使用：

- 窗口 `GetWindowRect` 动态计算；
- 相对位置（右上角、编辑框百分比）；
- 颜色/形状定位（绿色发表按钮）；
- 多个候选点 + 结果检测（相机按钮）。

仍然保留了少量相对坐标，因为微信的 Qt 界面是自绘的，UIA 树基本为空。

## “照片未发送”检测

微信图片上传失败时，不会创建正常帖子，而是在朋友圈信息流右侧叠加一条深灰色提示：

- 背景约 `#4D5154`；
- 左侧红色圆形感叹号；
- 白色“照片未发送”文字。

检测逻辑：

1. 只扫描信息流右侧、中部偏上区域（不是整个信息流）；
2. 按行统计“深灰像素 + 红色像素”；
3. 连续行组成候选条；
4. 发布前后计数比较，只有新增才判定失败。

早期版本扫描区域过大，会把封面/图片里的深色和红色误判为失败条；v1.0.1 已收窄区域。

## 失败清理

出错时按顺序尝试：

1. `Esc` 关文件框；
2. `Esc` 关编辑框；
3. 出现“将此次编辑保留?”时点“不保留”；
4. 如果编辑框还在，点“取消”再点“不保留”。

整个过程不会点“发表”。

## 已知限制

- 仅支持图片 + 文案；
- 依赖微信 4.x 当前 UI；
- 微信版本更新可能导致候选坐标失效；
- 锁屏时无法操作；
- 账号被限制/图片上传通道异常时无法绕过。
